## 和设备实际值的差别（2026-11-09 核对）
设备里存的成像参数和这里的文件有几处不同。依据是 ZL1107 四段录包里两台的设备回读（录包内 `sources/lidar/<left|right>/*/device_after_start.txt`）：四段一致，两台固件都是 XTFW-RT-V2.34.2。
| 项 | 左：文件 → 线上值 | 左：设备 | 右：文件 → 线上值 | 右：设备 |
|---|---|---|---|---|
| 第 1–3 档调制频率 | 0 → 1 | 1 | 0 → 1 | 1 |
| 第 4 档调制频率 | 3 → 7 | 3 | 3 → 7 | 3 |
| 第 5 档调制频率 | 2 → 0 | 3 | 3 → 7 | 3 |
| 第 5 档积分时间 `int5` | 0 | 200 µs | 200 µs | 200 µs |
| 灰度积分时间 `intgs` | 2000 µs | 2000 µs | 2000 µs | 40000 µs |
| 频率通道 | 文件里没有 | 0 | 文件里没有 | 2 |

"线上值"是驱动用 `include/wc_xt_driver/xtcfg.hpp` 的 `frequency_wire()` 把文件里的档位换成的命令值（0→1、1→3、2→0、3→7、4→15、6→4），设备回读的就是线上值。HDR、第 1–4 档积分时间（1600/200/30/1600 µs）、最小幅度 70、帧率 10 两边相同。

不要用 `apply_xtcfg` 写设备：
- 面板、实时建图和 `wc_phase1 capture` 都固定传 `device_config_policy:=preserve_current`，只用文件里的主机滤波，不写设备成像参数，所以现有录包不受这些差别影响。
- `wc_phase1 drivers|record --device-config-policy apply_xtcfg`、launch 参数 `device_config_policy:=apply_xtcfg` 会按文件改写设备：左雷达的第 4、5 档频率和 `int5`，右雷达的第 4、5 档频率和灰度积分时间。频率一变，测距行为就和以前的录包都不一样。频率通道驱动没有设置入口，不会被改。
- 驱动不发保存命令，改过的值断电后还在不在没有验证过。
- 确实要改设备参数时，先把文件改成只差想改的那一项，用 `wc_phase1 drivers --probe` 只读核对，写清怎么改回，用户同意后单独做。

## 改成像参数的室内对比（2026-11-11）
为了去掉 12 MHz 的相位折叠假点，A 在房间里把两台改成 9 组设置各录 30 s，结论是设备保持上表的原设置。证据在数据盘 `reports/lidar_frequency/20261111T1445Z_room/README.md`。
- 改调制频率会破坏测距：3 m 平面残差从约 11 mm 涨到 51–127 mm，有的组还有 4–5 % 的比例误差。出厂标定只对 12/6 MHz 这一套有效。
- 第 1、4 档积分时间要一起改；只改一档也会破坏精度。
- 固件会用第 4、5 档的 6 MHz 给 12 MHz 解模糊，但只对回波够强的像素（幅度约 350 以上）。折叠假点是更弱的远处回波，改积分时间只会挪动折叠的范围。
- 更正（2026-11-13）：11-11 23:26 以后两台连不上，不是雷达断电，是 Orin 网口 eno1 卡住了（总管 11-12 22:15 查清，重启 Orin 后恢复）。设备里一直是 23:18 写的 int1 = int4 = 800 µs，"断电后还在不在"仍没有验证。
## 厂商的设置（2026-11-12）
厂商 11-12 用上位机改了两台的成像参数并存进雷达，设备现在不是上表的原设置：左 int1 800、int4 2500、minLSB 80；右 int1 1000、int3 20、int4 2500、minLSB 80、频率通道 2→3。读回在总管的 `field/vendor_settings_20261112.md`。
- 核对、改回按名字做：数据盘同一证据目录的 `restore/restore.sh`。不带参数只读，打印两台各是哪套设置（s0 原设置、vendor 厂商设置）；`restore.sh s0` 或 `restore.sh vendor` 按名字写回驱动能写的项，再逐项读回。
- 频率通道和保留字节驱动写不了，核对时只列出。偏移 61 跟着第 1、4 档的配对变（等长、频率 2:1 时 0x18，否则 0x00），厂商的设置 int1 ≠ int4，所以是 0x00。
- 厂商这组第 1、4 档不等长。11-11 同类的 I1 在房间里 3 m 平面残差 57–90 mm，要量过才能用；量法在上面那份 README 的"厂商的设置"一节。
