# 规划与控制设计

本文说明自主导航里路径规划和运动控制怎样适配这辆轮椅的外形和这栋楼的窄通道，以及选择默认方案的依据。总体结构见[自主导航总体框架](autonomy_framework.md)，用法见[规划与控制操作](../operations/navigation_planning.md)。

## 车体：一个外形贯穿仿真、影子运行和代价地图

车体用 `NavProfile` 描述：默认是 0.55 m 圆（假设值），或一个凸多边形 `footprint`（车轴中点为原点，x 前 y 左）。同一个外形进入：

| 环节 | 用法 |
|---|---|
| 全局代价地图（规划） | 外形加 0.10 m 余量；NavFn、Smac 2D、Theta* 按加余量后的内切半径通过，Smac Hybrid-A* 和 State Lattice 在每个朝向检查完整外形 |
| 局部代价地图（控制器碰撞检查） | 外形本身，不加余量 |
| 碰撞监控 | 外形外扩 2 cm 为停车区，外形本身为接近模型 |
| 仿真碰撞真值 | 外形本身（`planning/body.py`） |

仿真碰撞对多边形逐格做分离轴检查：外形与格子正方形有面积重叠才算碰撞，只接触不算，与圆的判据一致；地图外按实体处理。每个物理步沿运动细分，相邻两次检查之间车体任一点的位移不超过半格（平移加转角乘外接半径），并把外形外扩半个细分步长，所以细墙不会被跨过，原地转向时车头扫到的范围也会被检查。圆形车体保持原来的检查不变。报告里多边形的间隙是外形到障碍格的精确距离（1 m 封顶），圆仍是车轴间隙减半径。

以前仿真按圆判碰撞、影子运行和代价地图按多边形，两者不一致：仿真里长车头原地转向撞墙不会被发现，或者按 0.55 m 圆过不去的窄道其实过得去。统一以后，仿真闭环的结论可以直接对照影子运行。

## 可选规划器与控制器

`planning/stack.py` 的 `PlanningChoice` 只替换 `GridBased` 规划器插件和 `FollowPath` 控制器插件，名字不变，行为树不变；默认选择（NavFn + RPP、无覆盖）生成的参数与原来逐项相同（有测试）。不倒车由插件类型和固定参数保证，命令行覆盖不能改动；运行前读回插件类型、不倒车设置和全部覆盖项。
