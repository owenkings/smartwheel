1. 关闭 RViz 或在建图终端按 Ctrl+C，等待本次采集停止、地图保存结束。
2. 备份 `hardware_setup.json`，修改实际发生变化的测量值及对应 `note`。使用合法 JSON：键名和字符串用双引号，不能添加 `//` 注释；说明写入 `note` 或 `_help`。
3. 在 Orin 上运行配置检查。此命令不打开 RViz，不启动传感器，也不验证实际安装、连接或地图精度：

   ```bash
   python3 /home/nvidia/wheelchair/scripts/map all --check-config
   ```

4. 检查通过后启动建图，可直接手推或在 RViz 内使用 WASD，无须收集启动静止窗口。下面均使用当前默认 `wheel_imu`，持续到关窗、Ctrl+C 或保留的磁盘/错误条件触发；具体模式的现场验证范围以本轮报告为准：

   ```bash
   python3 /home/nvidia/wheelchair/scripts/map right
   python3 /home/nvidia/wheelchair/scripts/map left
   python3 /home/nvidia/wheelchair/scripts/map all
   ```

这三行是三种选择，每次只运行其中一行。参数在启动时读取，运行期间修改文件不会改变当前地图。每个新会话保存采用的 `hardware_setup.json` 原文、SHA-256 校验值和编译后的参数；轮反馈预览及位姿估计共同使用该会话的 `wheel_candidate.json`。旧地图和旧录制不会自动重新处理。`--config` 指定的是建图入口配置，日常修改硬件安装只需编辑上述文件。

默认启动输出应为 `odometry_source: wheel_imu`，RViz 显示“轮速 + IMU 里程计”。检查 `prior/status.json` 已初始化且持续转发，`health/status.json` 的 `odom`、`prior_odom`、`cloud_map`、`grid_map` 已收到；不等待 ICP 或 `OdomInfo`。来源和里程计沉默时保持等待，不以年龄结束会话；缺段和被退役的旧云记录在先验覆盖诊断。磁盘与保存门仍有效，连续五次 ICP 失跟停止只适用于显式 `icp` 模式。详细启动与监视步骤见[操作指南](mapping_app_zh.md)。

`--duration` 仅兼容旧命令，接受任意非负整数但所有值均忽略，实际 `duration_s=0`。例如 `--duration 60` 也不会在 60 秒结束，需关窗或 Ctrl+C。没有运行倒计时或 12,000 累计帧数门，仍可能因真实设备/协议/写盘错误、显式 ICP 失跟或磁盘余量保护停止；磁盘并非无限容量。

**位置与角度怎样填写**

轮轴坐标原点为两个驱动轮中心连线的中点。以下左右方向均以坐在轮椅上朝前看为准：+X 朝前、+Y 朝左、+Z 朝上，是右手坐标系。

| 字段 | 顺序与单位 | 测量基准 |
| --- | --- | --- |
| `lidars.left.position_m`、`lidars.right.position_m` | `[X, Y, Z]`，米 | 雷达光学坐标原点相对轮轴中点的位置；目前以镜片中心卷尺测量近似 |
| 雷达的 `rpy_deg` | `[Roll, Pitch, Yaw]`，度 | 由该雷达的 `rotation_reference` 指定 |
| `imu.position_m` | `[X, Y, Z]`，米，或 `null` | IMU 原点相对 `parent_frame` 的位置，用父坐标轴表达 |
| `imu.rpy_deg` | `[Roll, Pitch, Yaw]`，度 | IMU 原生正轴相对 `parent_frame` 的固定旋转 |

例如，镜片位于轮轴中点前方 34 cm、左方 31.25 cm、上方 52 cm，应填 `[0.34, 0.3125, 0.52]`。右雷达横向位置为负数。这里的 Z 是相对轮轴中点的高度，不是离地高度。

地图初始原点在参考雷达光心，Z=0 也不是地面。轮轴中心高于地面约一个轮半径；按当前水平停车假设，光心离地约为 `0.52 + 0.165 = 0.685 m`，因此地面点出现在约 −0.685 m 合理。这是安装与轮半径候选的解释，不是对真实地面平整度或高度的测量。

旋转采用 `Rz(yaw) × Ry(pitch) × Rx(roll)`，把传感器坐标变换到参考坐标。对于朝前、基本正立的盒子，小角度方向可按下表理解：

| 参数增加 | 转轴 | 可观察到的方向 |
| --- | --- | --- |
| Roll 增加 | +X | 左侧抬高、右侧降低 |
| Pitch 增加 | +Y | 前方降低、后方抬高 |
| Yaw 增加 | +Z | 镜片前向朝左偏转 |

旋转顺序有影响，组合姿态不能简单逐项相加或相减。对已经明显转向或翻转的传感器，应按完整坐标变换测量，不能继续只凭“哪一边高”套用小角度说明。静止 IMU 的重力方向只能确定两个倾斜自由度，不能测出雷达之间的相对 Yaw；Yaw 需机械方向测量或独立标定。

**水平测量与轮轴安装角的区别**

`rotation_reference` 有两种值：

| 值 | `rpy_deg` 的含义 | 适用场景 |
| --- | --- | --- |
| `calibration_level` | 当次安装测量时，雷达相对共同水平参考的姿态 | 用静止 IMU 或水平仪测盒子倾角；还需记录同次轮轴/车架参考姿态 |
| `axle` | 雷达相对轮轴坐标系的固定安装姿态 | 已直接测得或标定传感器相对轮轴的外参 |

采用 `calibration_level` 时，`calibration_reference.axle_rpy_deg` 表示**那次安装测量时**轮轴坐标系相对同一水平参考的姿态。程序使用

```text
R_axle_lidar = transpose(R_calibration_axle) × R_calibration_lidar
```

换算固定安装旋转。当前主入口直接采用配置的轮轴参考轴向，不做本次实时重力找平，也不会因停车地面倾斜而改写外参。这里的 `calibration_level` 是安装测量时的参考，不代表每次启动都会测量世界水平面。

当前文件记录的测量值如下；文件本身保留更完整的小数：

| 项目 | Roll | Pitch | Yaw |
| --- | ---: | ---: | ---: |
| 左盒测量 | −2.963° | +5.053° | 0°，依镜片朝前的安装说明取值 |
| 右盒测量 | +3.275° | +3.497° | 0°，依镜片朝前的安装说明取值 |
| 测量时轮轴参考 | 0° | 0° | 0° |

最后一行**没有独立测量依据**：当前 `status` 是 `ASSUMED_LEVEL_NOT_MEASURED`，零角只表示试验中假设车架当时水平，不能视作已完成轮轴安装标定。独立测得参考姿态后，可填写该次测量对应的角度，并把状态改为 `USER_MEASURED_EXPERIMENT`。保留前一状态时三个角必须为零。两个状态都不表示已通过正式精度验收。

同一份 `calibration_reference` 必须对应所有使用 `calibration_level` 的雷达记录。若另一天只测一个雷达、轮椅的整体姿态已经变化，不要把这次读数直接混入旧参考：应在同一固定车姿态下重新测量所需记录及参考姿态，或先换算为相对轮轴安装角，再对该雷达使用 `axle`。

**移动硬件时改哪些值**

| 实际变动 | 应修改的字段 |
| --- | --- |
| 雷达只平移，方向保持不变 | 对应雷达 `position_m` |
| 雷达发生旋转 | 对应雷达 `rpy_deg` 与明确的 `rotation_reference`；若旋转支架同时移动原点，也更新位置 |
| 雷达带着 IMU 一起移动，二者相对安装不变 | 更新雷达外参；IMU 的 `parent_frame` 和相对 `rpy_deg` 保持原实测关系 |
| IMU 从左盒移到右盒 | 更新 `imu.parent_frame`、相对右雷达的 `rpy_deg`，以及已测得的相对位置 |
| IMU 改固定到车架 | `imu.parent_frame` 改为 `axle`，填写相对轮轴轴向的固定安装角和可获得的位置 |
| 轮轴位置、轮径或轮距改变 | 重新测量受影响的所有位置/安装关系，以及相关轮参数 |

例如，将 IMU 同轴固定在右雷达上，+X、+Y、+Z 分别与右雷达的正轴平行，可将 IMU 段改为：

```json
"imu": {
  "parent_frame": "lidar_right",
  "position_m": null,
  "rpy_deg": [0.0, 0.0, 0.0],
  "note": "IMU同轴固定右雷达；相对精确位置尚未测量"
}
```

“安装在右盒”本身不代表同轴，必须核实正轴。正立且朝前时，+Y 应朝轮椅左方：在左盒是外侧，在右盒是内侧。不要仅把 Y 数值反号来表示安装改变；单轴镜像不是合法的三维刚性旋转。

`imu.position_m: null` 是明确记录尚未测得位置。当前运动预测使用轮纵向速度、三轴陀螺和固定安装参考；不要求静止重力初始化，不实测陀螺零偏（采用明确标记的零假设），也没有对 IMU 线加速度积分或用 IMU 平移做线加速度杆臂补偿。因此，仅修改 IMU 的位置数值不会改变当前预测；IMU 安装旋转会影响陀螺方向。雷达相对轮轴的位置会参与转弯杆臂计算，需要准确填写。

**轮参数与检查范围**

`wheel_odometry` 中 `wheel_radius_m` 是有效轮半径，`track_width_m` 是左右驱动轮轮距，`register_to_wheel_rpm` 是原始反馈到轮速 rpm 的比例，`left_sign` / `right_sign` 是各侧方向符号。当前这些数值仍来自历史候选，尚未完成本工程的距离及转弯标定。移动电控盒通常不改变这些机械/反馈比例；更换轮胎、传动或反馈约定时才应按测量结果调整。修改时保留 `state: "UNVALIDATED"`、`formal_odometry_eligible: false`，并在 `provenance` 写明来源。

配置检查会拒绝缺失几何参数、拼错的未知字段、非数值或无限值、超出 −180° 至 +180° 的角度，以及长度超过 3 m 的位置向量。它验证格式、支持范围和旋转计算，不能发现“填写的数字与实际安装不符”。不要把不确定值填成零以绕过检查；IMU 未知位置可显式用 `null`，未知安装旋转应先测量。

**WASD 软件参数与手推**

`manual_controls` 随每次建图保存快照。`arm_allowed` 沿用兼容字段名，当前表示允许用户直接按 WASD，不再表示需要点击启用按钮。首次非零按键才初始化；松键后归零，空闲 0.75 秒释放伺服，下一次按键自动重新初始化。

| 字段 | 当前值 | 含义 |
| --- | --- | --- |
| `arm_allowed` | `true` | 连接就绪后直接接受 RViz 内的 WASD；设 `false` 禁止控制写 |
| `reason` | 2026-09-14 用户要求直接 WASD 与手推切换 | 软件授权来源 |
| `max_linear_m_s` | 0.10 | 直行速度候选，单位 m/s |
| `max_angular_rad_s` | 0.20 | 转向速度候选，单位 rad/s |
| `command_rpm_to_register_scale` | 8.9 | 目标轮速 rpm 到控制寄存器的比例候选 |
| `operation_evidence.status` | `USER_REPORTED_LEGACY_OPERATION` | 历史操作证据分类，不是固件、看门狗或本次实车验收 |

命令比例 **8.9 register/rpm** 与反馈比例 **0.112 rpm/raw** 是两个独立方向的转换，不能互相替代。轮径、轮距和方向符号统一来自 `wheel_odometry`。

无启用按钮、专用控制区焦点或运动总时限；本地连接临时中断自动重试，恢复不沿用旧键。250 ms 按键有效期和 500 ms 后端状态有效期仍清除陈旧输入，但不会要求人工重新激活。全程没有有效方向键时，不会发送伺服或速度写入。手推释放采用旧驱动已实现的 `0x200E=7` 分支，释放后没有零速保持；软件测试不证明实物停车、释放或断线行为。

完整操作、连续等待行为和 NoMachine 断网限制见[操作指南](mapping_app_zh.md)。修改文件后需正常结束旧会话再启动，重连不会改变运行中保存的许可快照。

**四路相机预览配置**

相机开关位于 `/home/nvidia/wheelchair/config/mapping_live.json`：当前 `cameras_enabled` 为 `true`，`camera_config` 指向 `config/cameras.json`。默认在同一 RViz 窗口显示左前、右前、左侧、右侧四路预览，不录制图片或图像话题，也不使用图像参与 ICP。关闭相机应修改 `cameras_enabled`；相机方向、USB 端口和预览规格应修改 `camera_config` 指向的文件，停止当前建图后、下次启动生效。

**点云发布与磁盘保存**

存储发布方式由 `/home/nvidia/wheelchair/config/mapping_live.json` 的 `archive_publication_mode` 指定，当前 `queued_realtime`：不可变原始 CDR 进入有界内存队列后发布，后台写 CDR 与索引。待写队列仍限制为 100 次输出、128 MiB，满则明确失败；这些是同时积压上限，不是累计记录数或保证可缓冲多少秒。

当前 `archive_checkpoint_policy=on_close`，运行中写记录，停止采集后集中同步并验证，不启用 256 次未 checkpoint 积压门。显式选择 `periodic` 时仍有 1 秒计划周期和 256 次未确认输出上限。主入口已取消 12,000 总归档上限，但没有扩大内存或消除底层慢盘。独立严格工具缺省仍保留其旧总量/新鲜度门，详见[当前限制清单](runtime_limits_zh.md)。

`DbSqlite3/InMemory=true` 让原生地图数据库在 RAM 运行，正常关窗时落到 `slam/rtabmap.db`。异常掉电/崩溃可能丢失 RAM 地图和原始归档中尚未写出/同步的内容。旧 `written_before_publish` 可选方式表示 write + flush 后发布，也不表示逐帧完成 fsync；两种方式都保持真实来源时间。

主入口 duration 参数兼容忽略，不设总时长或累计帧数停止。每秒检查实际会话文件系统，空闲 ≤2 GiB 时以 `STORAGE_LIMIT_REACHED` 正常提前收尾并尝试导出；空间读取错误仍失败。归档底层约 1 GB 写盘保护、导出前原库大小 +512 MiB 余量要求仍有效；余量不是保存成功保证。

正常关闭必须排空队列、完成最终 checkpoint/fsync，并通过索引、CDR、数据库和产物完整性检查才能报告 `SAVED`。主入口持久化预算 90 秒、原生收尾 105 秒、组件 grace 120 秒、监督 CLI 总预算 166 秒，导出程序最多 180 秒。这些停止期预算与电机停车响应时间不同。不要通过修改硬件安装参数绕过存储错误。

SourceFrame 的 SDK `raw` 云已做深度解码和镜头投影，只是尚未做主机基础滤波；原样保存 CDR 不等于录到了原始相位或 UDP。`raw_count` 表示总像素，`valid_count` 表示 XYZ 全有限的有效点。第 14、15 轮约 9000→5000 的突变是有效点数变化；同帧 raw/filtered 已按身份、epoch、序号及滤波前哈希配对。当前没有逐帧原始 depth、unit_div、HDR/frequency 等证据，尚不能区分设备输出与 SDK 解码原因，不宜通过猜测安装参数补偿。

**连续模式之前的历史实验记录**

以下保留历史 ICP 模式的原数字与成败；其中静止启动、3 秒超时、旧帧数/积压门描述当时版本，不是当前 continuous 主入口行为，也不是当前 `wheel_imu` 验收结果。

轮日志当前按 FIFO 在独立 writer 中合批，不丢弃原始读取、请求/响应和意图记录。预算为 1024 条事件与 4 MiB，包含正在写出的批次；单条最多 64 KiB。每批最多 64 条或 64 KiB，最多额外等待 50 ms 聚合后一次 write + flush。按 10 Hz、每次四条日志换算的 25.6 秒仅是数量预算，字节限制可能更早达到，不保证任何固定可承受阻塞时长。独立工具原默认 close 为 10 秒；统一建图入口在编号 22 后接入下述单独的 90 秒停止期持久化等待。停止后不再等待聚合；即使结束记录被队列拒绝，也会尝试排空并最终 fsync，原失败仍保持 `FAILED`。写入、超预算、短写或关闭失败不被隐藏，来源阈值与控制授权不变。
