# 一条命令建图：操作指南与验证记录

更新日期：2026-09-14。当前 `scripts/map` 强制使用连续建图模式：**无总时长或 12,000 帧上限，无启动静止要求；数据暂时沉默时等待恢复，不按数据年龄退出。** 默认 `wheel_imu` 由轮反馈和 IMU 提供位姿，不启动 ICP 里程计。完整保留限制见[当前限制清单](runtime_limits_zh.md)，本轮更改、退出诊断和验证进展见[连续建图简报](../../reports/continuous_mapping_20260914/README_zh.md)。本文不以历史静止保存结果替代当前版本的真车与动态精度验收。

## 一条指令启动

在 Orin 能访问当前桌面的终端执行，无需先切换目录：

```bash
python3 /home/nvidia/wheelchair/scripts/map right
```

`right` 可替换为 `left` 或 `all`。每次只运行一个会话，入口统一启动雷达、H30、轮反馈、相机、建图与 RViz；不要另开旧底盘/WASD 程序争用串口。它仍检查主机、桌面、设备身份、独占锁和安装配置。

| 模式 | 输入和参考 |
| --- | --- |
| `left` | 左雷达、H30、轮反馈；参考原点在左雷达，轴向采用配置的轮轴参考。 |
| `right` | 右雷达、H30、轮反馈；参考原点在右雷达，轴向采用配置的轮轴参考。 |
| `all` | 两雷达、H30、轮反馈；左雷达为点云基准，右云使用固定安装变换和已覆盖的时间差补偿。配对仍要求 ≤50 ms；缺一侧等待，不自动改成单路。 |

`left/right` 只选择主机采集来源，不向另一台雷达发送停止指令，不能据此证明它停止照射或排除光学互扰。

指定新名称及保存目录：

```bash
python3 /home/nvidia/wheelchair/scripts/map --mode all --name room_a_01 \
  --output /home/nvidia/wheelchair/reports/maps/room_a_01
```

| 参数 | 当前含义 |
| --- | --- |
| `left/right/all` 或 `--mode` | 必选模式；两种写法同时使用时必须一致。 |
| `--name NAME` | 1–64 个 ASCII 字母、数字、下划线、点或横线，字母/数字开头；缺省生成 UTC 时间和随机后缀。 |
| `--output PATH` | 工程内尚不存在的新会话目录；默认 `reports/maps/<会话名称>/`。相对路径从工程根解释，不能穿过符号链接/联接。 |
| `--duration N` | 兼容保留，接受任意非负整数，默认 0；**所有值均忽略，实际运行不计时**。例如旧命令 `--duration 60` 也需关窗或 Ctrl+C 结束。 |
| `--config PATH` | 工程内运行配置，默认 `config/mapping_live.json`；控制器强制 `continuous_mapping=true`。 |
| `--check-config` | 只核对配置与变换，不启动传感器、窗口或电机。输出应有 continuous=true、无 duration/archive 上限及无静止/新鲜度停机门。 |

运行配置和安装参数在启动时保存快照，不热加载。修改雷达/IMU 安装与轮参数的方法见[硬件参数指南](hardware_setup_zh.md)。

## 启动、移动与数据恢复

启动后可直接手推，也可在 RViz 内使用 WASD；不必等待静止窗口。输入使用固定安装参考立即生成配置，里程计在真实 IMU 与轮反馈均出现后初始化。缺来源时保持等待，没有首帧、15 秒配置、30 秒静止启动或 3 秒里程计失鲜截止。

本次不做实时重力找平或陀螺零偏实测。参考轴向来自安装配置，初始陀螺零偏采用零假设并明确标记 `NOT_ESTIMATED_ZERO_ASSUMPTION`；停车在坡上也不会自动校成世界水平面。安装方向、轮比例与零偏误差仍影响地图。

雷达或 IMU 暂无新帧、轮/IMU 历史有正向缺口时，建图等待合法数据恢复。缺段不积分末速度，也不把未知运动补成连续轨迹；位姿保持，待真实新数据恢复后接续。过旧或无运动历史覆盖的云会丢弃并计数，双路未配对云也会退旧。`prior/status.json` 的 `motion_coverage_complete`、覆盖 gap 与丢弃计数用于说明这些缺失。

等待不会掩盖真实设备错误：SDK 明确断开、串口 EOF/应答超时或错误、CRC/身份/时间倒退、磁盘写失败仍可结束会话。主入口取消的是单纯数据年龄导致退出，不是所有错误检查。

## WASD 与手推

当前 `manual_controls.arm_allowed=true`。RViz 本应用收到键盘时直接接受 W/A/S/D，Space 清键停车；不需启用按钮或专用控制面板焦点，也不定期取消激活。首次非零方向键才初始化伺服，沿用旧流程的两段 0.2 秒等待。

- 首次 WASD 前只读取轮反馈，不因建图启动而抱闸，可直接手推。
- 松键后发零速，空闲 0.75 秒后通过旧驱动 `0x200E=7` 分支释放；释放后可手推，下次方向键自动重新初始化。
- 连续有效按键无运动总时限。250 ms 意图失效或 500 ms 后端状态失鲜时清键停车；连接恢复后新按键可继续，无 10 秒永久放弃。
- 切出 RViz、隐藏控制面板、关闭窗口会清键。系统或远程桌面仍需把真实键盘事件投递给 RViz；应用没有全系统键盘监听。
- 当前指令上限为直行 0.10 m/s、转向 0.20 rad/s；发送非零前要求 0.25 秒内的轮反馈。真实串口错误仍进入 FAULT。

NoMachine 网络断开不保证远端 RViz 立即失去焦点；软件心跳不能证明操作者仍在线。现有软件测试不代替实物停车、伺服释放、硬件看门狗和 USB/RS485 物理断线验证。详细协议和退出预算见[限制清单](runtime_limits_zh.md)。

## 在 RViz 看什么

默认布局为左侧显示/视角标签、中间地图、右侧四路相机、底部 WASD。`Views` 可切换斜视或俯视；粉色“实时点云（当前帧）”显示新输入，累计三维地图和二维地图分别显示建图产物，轮椅仅为示意模型。改变本次视角不修改安装外参或导出几何，关窗丢弃临时视图修改后仍进入保存。

默认 `wheel_imu` 应看到“轮速 + IMU 里程计”，不等待 ICP 或 `OdomInfo`。检查 `prior/status.json`、`health/status.json` 中计数、消息年龄与 `waiting_outputs`；地图画面保留并不证明来源仍持续更新。该模式关闭扫描修正与回环，轮滑、比例误差和陀螺漂移不会被 ICP 自动纠正。显式 `odometry_source=icp` 仍有连续五次失跟停止，不自动与 wheel_imu 互相切换。

四路相机只作预览，不录图、不参与当前位姿估计。当前配置请求 320×240 MJPG、30 fps 采集、8 Hz 发布；实际新帧率以状态和画面为准。单路 3 秒读超时仍可退出并按限定条件重开，最多两次；相机过期不等于核心地图必须失败。相机具体配置和降级状态见[硬件指南](hardware_setup_zh.md)。

当前 RViz 使用会话范围的软件渲染；指定启动 GL drawable 故障符合条件时只重试一次窗口。它不是任意窗口崩溃自动恢复，也不能保证图形问题已全部解决。

## 结束与保存

关 RViz 或在启动终端按 Ctrl+C，等待终端从 `STOPPING_AND_SAVING` 进入最终状态。没有时长/累计帧数门仍不代表无限资源：每约 1 秒检查磁盘，剩余 ≤2 GiB 时以 `STORAGE_LIMIT_REACHED` 正常提前收尾并尝试导出。主保护不是保存保证；底层约 1 GB 写盘保护、100 输出/128 MiB 待写队列和真实 I/O 错误仍可使会话失败。

当前原始归档是 `queued_realtime` + `on_close`：先进入有界内存队列后发布，后台写记录，停止后集中最终同步；没有运行期 256 个未 checkpoint 输出门。显式选回 `periodic` 才恢复该 256 门。RTAB-Map 数据库在 RAM 运行，正常关闭落盘；断电或杀进程可能丢失尚未持久化的数据。

保存仍有期限：各持久化组件 90 秒，原生收尾 105 秒、组件 grace 120 秒，监督 CLI 总预算 166 秒；原生导出程序最多 180 秒。不要把窗口关闭当作保存完成。导出前还要求剩余空间至少为数据库大小 +512 MiB，并核对数据库、bag、checkpoint、索引与地图非空。

| 文件或状态 | 用途 |
| --- | --- |
| 终端最终 JSON 的 `status` / `errors` | 本次整体结果，`SAVED` 才表示保存检查通过；等待恢复不是失败，也不等于已保存。 |
| `.phase1_runtime/sessions/<session>/mapping_app/manifest.json` | 受管组件退出码与整组收尾原因。 |
| 会话内 `input/status.json`、`prior/status.json`、`health/status.json`、`wheel_status.json` | 输入/配对、运动覆盖、输出健康和轮控制诊断。 |
| 会话内 `slam/rtabmap.db` | 原始地图数据库；存在或 integrity=ok 本身不代表整个会话成功。 |
| 会话内 `export/result.json` | 正常导出的完整结果及实际文件路径；主程序不另写同名顶层结果文件。 |

`SAVED` 不证明地图真值精度、路线完整覆盖、长期漂移或导航安全。失败时保留原件，不把部分数据库恢复改写为整场成功。本轮一次 3 秒数据沉默引发退出的诊断及独立部分地图导出见[连续建图简报](../../reports/continuous_mapping_20260914/README_zh.md)。
