# 双雷达框选平面与多姿态标定

本功能使用已经完成的静止录包，分别拟合左右雷达看到的同一板面，组合多个方向求解 `T_left_right`，再用留出的独立录制检查结果。页面可运行逐姿态点到面 ICP 并保存离线报告。它没有采集或正式外参启用入口。

## 与其他任务并行

- 软件位于新增 `src/wc_calibration/plane_*.py`、`plane_assets/` 与 `scripts/lidar_plane_workbench`，不修改融合、实时面板或正式配置。
- 工作台只监听 `127.0.0.1`，使用独立随机端口；可与其他离线融合任务同时打开。计算采用单线程数值库。
- 真正录制仍由现有录制工具独占设备。开始每一次录制前确认其他窗口没有采集、预览或占用设备的建图任务；不要同时启动两个设备读者，不停止未知任务。
- 数据、工作区和结果经过当前 `StoragePolicy` 写入配置的 USB。USB 丢失、挂载身份或存储配置变化时拒绝继续，不回落到主机磁盘。

## 板子准备和位置

1. 先用现有盒子最大、最平整的一面；纸张需贴实，盒面不能鼓起或晃动。约 60×40 cm 的连续平面便于框选，这是操作建议，不是精度标准。若板面始终不通过质量检查，再换更平整的硬板。
2. 图案只帮助认出目标，本方法不再点击黑白角点。左右雷达都要看到同一面；框内不要包括另一侧面、纸边、折痕、胶带、遮挡或背景。可优先选平整的哑光白色区域。
3. 第一姿态先从约 1.5 m 距离尝试，以两侧幅度图都能完整看到板面为准，再调整距离和高度。四周留出余量，避免板面被视野顶部截断。
4. 雷达安装和轮椅位置在整组标定期间固定。只在两次录制之间改变板子的方向；不能拿在手里摇晃着录制。固定后人退到共同视野之外。
5. 已量的十字宽约 191 mm 只可粗略检查尺度，没有测量不确定度，不能当作标定真值。

## 建议的 6 个训练姿态和 3 个验证姿态

角度是摆放起点，最终看工作台法向矩阵的秩和条件数。2026-10-11 用户决定明天再录制，原来正反两个上下倾姿态不便固定，改用一次固定斜撑：先录直立组，再保持同一种上下倾角，连同支撑一起水平转动录第二组。无需分别做“上边靠近”和“下边靠近”。仅改变距离或高度、或始终让板直立并只左右转动，不足以补齐竖直方向约束。始终确保每次录制中左右雷达看到同一物理面。

| 标签 | 摆放方法 | 页面用途 |
|---|---|---|
| T01 | 板面基本正对双雷达 | 参与标定 |
| T02 | 左边缘比右边缘靠近，左右倾约 25–35° | 参与标定 |
| T03 | 右边缘比左边缘靠近，左右倾约 25–35° | 参与标定 |
| T04 | 用固定斜撑保持一种方便的上下倾角约 20–30°，水平方向正对双雷达 | 参与标定 |
| T05 | 保持 T04 的上下倾角和支撑，整体水平向左转约 25–35° | 参与标定 |
| T06 | 保持 T04 的上下倾角和支撑，整体水平向右转约 25–35° | 参与标定 |
| V01 | 重新摆成基本正对，可前后移动约 20 cm 后固定 | 独立验证 |
| V02 | 另摆一个左右倾约 25–35°的姿态 | 独立验证 |
| V03 | 复用同一种固定斜撑，另选位置固定，水平方向基本正对 | 独立验证 |

V01～V03 必须另外录制。即使摆法接近训练姿态，也不能复用训练录包或把同一录包的不同帧当验证。

如果连一次斜撑也难以实现，可考虑双方都能看到足够大有效区域的箱子顶面或水平硬板。不同姿态可使用不同平面，但同一次左右必须框同一面；先检查点数、跨度和质量，再确认是否可替代。

## 每个姿态怎样录制

由本聊天总控检查设备占用、存储身份并调度录制；其他聊天的硬件任务结束或释放设备后才开始。用户每次摆好并固定一个姿态，保持轮椅、雷达、板子和共同视野内目标静止，直到收到“录制和保存完成”的提示。正式采集窗口为 20 秒，启动准备与转存校验需要额外时间。

现有录制入口的参数示例（供总控逐姿态执行，不要在其他设备任务运行时直接启动）：

```bash
cd /home/nvidia/wheelchair
bash scripts/wc_phase1 capture --profile mapping_core --session plane_T01_20261011_210000 --duration 20 --staging memory --sides all
```

每次使用新的 session 名，替换 T01 与时间；不要添加 `--manual-drive`、`--preview` 或 `--diagnostic`。该 profile 也记录现有被动辅助数据，标定工作台只读取两侧原始雷达数据。等最终状态 `COMPLETE` 且 `recording_complete=true` 后，保留工具返回的完整录制目录，再换下一个姿态。录制失败或未完成的目录不能导入。

## 工作台操作

1. 导入一个完成的目录，标签填 T01 等，T01～T06 选“参与标定”，V01～V03 选“独立验证”。同一录包不能重复导入。
2. 左右幅度图分别拖拽框住同一板面内部的一大片平整区域。两侧框不必相同大小。框内要有二维面积，不能只框一条边或很小的一块。
3. 勾选“左右框内是同一块板的同一面”，检查“拟合左右平面”结果。修改框选会使该姿态的历史拟合失效。
4. 检查两侧支持率、内点及全部点残差、空间跨度和同录制帧间稳定性。若拒绝，先看原因：包含背景则缩到纯板面；点太少或跨度不足则扩大纯板面或调整摆板后重录；板面残差或帧间变化大则检查平整度、反光、晃动和遮挡。不能靠增大门限强行通过。
5. 逐姿态导入和检查后，点击“计算多姿态标定”。看训练与验证逐姿态的法向夹角、平面偏移、法向矩阵秩和条件数。至少 3 个训练录制法向独立；完整验证另需至少 3 个法向独立的验证录制。
6. 候选被允许后，点击“运行离线 ICP 检查”。它只在同一姿态的两侧板面内寻找对应，训练姿态参与优化，验证姿态只评估。比较前后残差、覆盖率及总旋转/平移变化，并在 XY/XZ/YZ 三个视图检查叠加。
7. 点击“保存会话与报告”，保留显示的结果目录。ICP 被拒绝时仍可保存诊断报告，不会启用该结果。

工作台当前用 3 cm 平面内点距离、75% 支持率、全部点 P95≤6 cm、双向二维跨度≥10 cm 等实验门限筛选单板面；多姿态残差门限为 3°、5 cm。通过这些门限不证明实测精度。帧间稳定性也不证明场景物理静止。

## 自动保存、恢复和结果含义

- 框选、拟合、用途等修改自动写到 `data/calibration/plane_workbench/<会话>/workspace.json`。浏览器刷新不会丢掉服务端已成功保存的框选。
- 服务重启时保留已绑定来源与选区，核对原始文件和存储配置，要求重新拟合、重新求解；历史报告中的系数不会被直接作为可信计算输入。同一工作区只能被一个服务打开。
- 显式保存的 `plane_calibration.json` 保留原始来源 SHA、选区、各姿态平面质量、训练/验证残差、初值与 ICP 结果；`complete.json` 标记离线导出完成。所有结果均为 `live_eligible=false`。
- 变换定义是 `p_left = R_left_right p_right + t_left_right`，单位米，原始轴约定 FLU。它求的是两个雷达点云坐标系之间的相对变换；不直接确定点云原点相对外壳、安装孔或轮椅基准的机械偏置。

在 Orin 上启动或恢复：

```bash
cd /home/nvidia/wheelchair
bash scripts/lidar_plane_workbench --duration 28800
# 恢复时将下面路径替换为该会话实际显示的 workspace.json
bash scripts/lidar_plane_workbench --resume /media/nvidia/tiany-USB/wheelchair/data/calibration/plane_workbench/实际会话/workspace.json --duration 28800
```

启动会返回 JSON 中的 URL，通过本聊天建立的 SSH 回环隧道访问；随机端口不是固定地址。关闭网页不等于停止后台服务，服务到期后需重开并恢复。
