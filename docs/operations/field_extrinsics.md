# 现场双雷达外参与轮速标定（不用标定板和卷尺）

这套方法用普通室内环境和手推行驶，求出两台 XT-M60 的安装姿态、左右相对外参和轮速比例。它取代了[木板多姿态方案](../environment_plane_calibration.md)：那个方案求不出雷达相对轮轴的关系，而且需要稳定固定多个倾斜姿态，已经暂停。

## 求什么、靠什么

| 量 | 依据 | 实测精度（2026-10-26） |
|---|---|---|
| 各雷达横滚、俯仰 | 墙面必须竖直：轮椅转了多圈，墙面在雷达坐标里出现各种方位，所有墙法向都垂直于"向上"方向 | 录包之间散布约 1–1.5° |
| 左雷达相对车体的偏航 | 平面手眼：雷达逐帧 ICP 里程计对齐轮速轨迹 | ±0.3° |
| 右雷达相对左雷达（偏航、平移） | 房间多处停顿，左右点云联合点到面配准；固定各自倾角，只求 4 个自由度 | 偏航 ±0.3°，平移 ±2–4 cm |
| 轮速比例 | 正对墙直线推近，雷达测到的墙距变化作真值 | 两次相差 1.9% |
| 雷达相对轮轴的位置 | 行驶数据求不准（±10 cm），沿用机械测量值 | — |

这几项方法互相印证。两种独立方法求出的右雷达相对偏航分别是 −4.15°（手眼）和 −4.56°（配准）。地面不用来定倾角，因为 ToF 雷达测地面有系统偏斜：2–3 m 外前倾 3–5°，墙根前 2–3 m 处可达 10–30°。墙面测得准。

## 现场录制（一次上楼约 30–40 分钟）

所有命令都在 Orin 本机终端运行。每条命令先显示步骤，按回车开始录制，看到绿色"开始录制"后再动作。录完当场显示合格或不合格及原因，不合格就照提示重录。

```bash
cd /home/nvidia/wheelchair
bash scripts/lidar_field_check check              # 只检查设备，不录制
bash scripts/lidar_field_check wall --dist 3.0    # 正对空墙 3 m 静止 20 s
bash scripts/lidar_field_check wall --dist 4.5
bash scripts/lidar_field_check approach           # 离墙约 4.5 m 推到 1.5–2 m，录两次
bash scripts/lidar_field_check room               # 房间里 5 处以上不同位置/朝向各停 4 s，可多录几次
bash scripts/lidar_field_check summary            # 进度
```

- 墙面距离从 3 m 起：最低一排光束要到约 2.2 m 外才照到地面，1.5 m 时看不到地面。
- 推向墙要两次结果相差 ≤3% 才算确认。
- 房间录制可以多次，结果会合并统计并剔除离群停顿。单处配准受视野部分重叠限制，散布约 ±3–5 cm、±1–2°，所以看的是多处合并后中位数是否稳定。
- 录制只读，不驱动电机，靠手推；推的人站在轮椅后面。结果写入 `data/calibration/field_check/`。

## 离线求解与验证

```bash
E=/media/nvidia/tiany-USB/wheelchair/data/experiments
F=/media/nvidia/tiany-USB/wheelchair/data/calibration/field_check
bash scripts/lidar_field_solve \
  --room $E/房间录包1 --room $E/房间录包2 \
  --level $E/房间录包1 --level $E/房间录包2 --level $E/走廊录包 \
  --motion $E/走廊录包 --motion $E/房间录包1 \
  --validate $E/走廊录包 \
  --approach-results $F/approach_某次.json --approach-results $F/approach_另一次.json
```

输出 `data/calibration/field_solve/<时间>/candidate.json`，包含 `T_left_right`、各雷达倾角、左雷达偏航、轮速比例，以及验证录包上的左右重叠残差（机械名义值对比候选）。`--validate` 的录包不参与求解。

写进正式配置前，用候选外参离线重建一张地图，与机械初值对比，确认墙面重影减少。确认后通过面板"设备参数"保存（会做版本检查、来源哈希校验和自动备份），外参状态标为 `USER_MEASURED_EXPERIMENT`，并附上依据文件。

## 2026-10-26 实际结果

- 输入：房间 `field_room_20261026_135242`、`_141419`，走廊 `zoulang_test3min_20261011_182932`，推墙 `field_approach_20261026_134450`、`_134909`。
- 右雷达在左雷达坐标中：x 8.6 cm、y −46.3 cm、z −3.9 cm，横滚 0.3°、俯仰 1.4°、偏航 −4.56°。
- 左雷达倾角 −0.03°/0.19°，偏航 0.4°；右雷达倾角 0.28°/1.58°，偏航 −4.16°。
- 轮速比例 0.93，轮半径 0.185 → 0.172 m。
- 走廊独立验证：左右重叠残差从 43 mm（机械名义值）降到 33 mm。重建走廊地图，在轨迹相同的情况下墙高区间 2 cm 体素减少 16%，目视确认重影减少。
- 已写入正式配置。改前的备份在 `reports/panel/parameter_revisions/20261026_155401_*`。

## 已知局限

- 无论用哪组外参，左右重叠残差都降不到测距噪声水平（约 25–35 mm 对 14 mm）。说明点云本身有畸变，刚体外参只能补偿一部分。
- 右雷达算出来比左雷达靠前约 8.6 cm、低约 3.9 cm，和对称的外壳布局对不上，未独立确认。下次现场量一下两个雷达盒前缘的前后差。
- 没有外部真值，不能宣称特定毫米级精度。
- 时间对齐（2026-10-27 离线估计，未写入配置）：按到达时间，轮速比 IMU 晚约 11 ms（4 份录包 8–23 ms），右雷达晚约 62 ms（55–72 ms），左雷达晚约 56 ms，但 4 份录包之间差到 34–85 ms，还不够稳定。方法是雷达 ICP 角速度、轮速差分角速度分别与陀螺 z 互相关，相关系数都在 0.97 以上。
