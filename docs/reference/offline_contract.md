# Offline data contract v1

This freezes the numerical and persistence API. The target adapters have since been compiled against the actual installed ROS Humble and RTAB-Map 0.23.7. Target Python 3.10, system NumPy 1.21.5 and SciPy 1.8.0 were verified with PYTHONNOUSERSITE=1; the unrelated user-site NumPy is not used. The current ROS message contract is in interface_contract.md.

All transforms T_A_B are 4x4 row-major arrays mapping B coordinates into A, metres and radians. Time is integer nanoseconds. Quaternion order xyzw. Identity left extrinsics define rig_link only; unknown right extrinsics remain null.

Calibration CLI consumes JSON: {schema_version:1, source_mode:"synthetic"|"real", sensor_ids:{left:...,right:...}, training:[{id, left:[[x,y,z],...],right:[[x,y,z],...]}], validation:[same], initial_T_left_right:4x4 or null}. The solver must reject repeated scene IDs/content across training and validation. A result contains status UNVALIDATED/CANDIDATE/VALIDATED, source_mode, T_left_right, diagnostics, input hash and versions. Synthetic results never become live VALIDATED.

Snapshot API input is a directory with snapshot.json, observations.json, graph.json, trajectory.json, calibration.json, config.json, and slam/rtabmap.db. snapshot.json contains schema_version, session_id, source_mode (synthetic|real), sensor_mode (dual|single_left|single_right), graph_epoch, graph_revision, completed_map_revision, frame_id, ground_valid, calibration_id, time_model_id. A complete snapshot requires graph_revision==completed_map_revision and every graph node mapped. observations.json is {observations:[{raw_key, sensor_id, side, node_id, odom_epoch, points:[[x,y,z]], T_node_sensor:4x4}]} where T_node_sensor already includes observation-time motion relative to keyframe. graph.json is {session_id,graph_epoch,revision,nodes:[{node_id,odom_epoch,T_map_node:4x4}],edges:[{from_id,to_id,type}]}. trajectory.json records rig_link poses. Missing association is an error, never silently skipped.

Offline map builder API accepts graph and observations dictionaries and config, returns a complete map with cloud, occupancy voxels, grid metadata and data, and revision. Use both original endpoints and original sensor origins; 2D free requires vertical coverage through configured collision interval plus ground evidence; unknown stays -1. Sparse 3D occupancy JSON/NPZ is permitted in place of .ot if honestly documented. Rebuild each revision from raw observations.

Map store exposes save_snapshot(snapshot_dir,map_id,version), verify(map_id,version), load(map_id,version), list_versions(map_id), and goals revision functions. Save must use SQLite read-only backup, complete revision validation, manifest hashes, same filesystem atomic commit and shared OS flock; reject traversal, symlinks, collisions. Saved versions immutable, goal edits create new version or external version-bound annotations with explicit review state. No ROS/hardware dependencies in numerical/store modules.

Document callable module paths and APIs in the corresponding module README and reference documentation. Place tests under the matching functional directory in `tests/`. Target-platform acceptance runs on Orin; Windows-only checks do not establish target behavior.
