# 建图采集期间写入，停止采集后集中同步

2026-09-14。适用于普通 `scripts/map` 的试验建图；不更改原始录包、旧故障状态或传感器数据。

## 问题与依据

`map_right_20260914T125443Z_100a36` 的 input/status.json 记录一次检查点耗时 50.901 秒。周期同步尚未提交时，累计接受帧数与已同步帧数之差达到既有 256 上限，input 抛出 STORAGE_CHECKPOINT_BACKLOG。此后没有新的输入点云，monitor 检出 odom 超过 3 秒未更新并关闭会话。IMU/轮反馈仍到达，轮速＋IMU此前已驱动34次三维与二维地图更新；这次不是ICP失跟，也没有达到2GiB空间阈值。

旧路径每秒安排一次周期检查点；即使逐帧写入已与回调分离，原始CDR、索引、目录和检查点清单的主动同步仍会与ROS录包、地图数据库共用存储。运行期多个独立写入也观测到约7秒延迟。日志证明存在存储同步长尾及对应的软件停止条件，没有证明磁盘硬件损坏或确定其底层原因。

## 决策

普通建图配置显式使用 `archive_checkpoint_policy: on_close`。原始CDR及索引仍逐帧写入并flush；实时发布仍遵守有界内存队列中的不可变数据已接受契约。录制期间不主动安排此归档的fsync检查点；停止采集并排空归档writer之后，才使用原有完整文件、目录、清单屏障同步全部已接受数据。

`periodic` 保留为显式选项，旧配置缺少字段时仍采用旧行为及256帧未同步上限。`on_close` 的周期及未同步帧数上限报告为null；实际未同步计数照常累加，运行期checkpoint保持null，不以已写入冒充已持久化。没有提高旧256上限来掩盖停顿。

两种策略均保留100项/128MiB实时归档队列、写入失败、设备数据新鲜度、磁盘空间检测，以及正常关闭、最终检查点完整覆盖、索引和文件检查、原生数据库关闭等导出条件。任何历史故障、写入失败或同步超时仍不能标记为正常保存。

## 取舍与验证边界

用户正常关闭时仍检查保存完整性；意外断电或异常退出前不保证原始记录已落盘。on_close减少的是录制期间主动同步的竞争，不增加磁盘带宽，也不保证OS后台回写、录包或其他进程不会阻塞。较长会话的全量收尾成本更大，现有90秒组件持久化预算不构成保存时间保证。

软件验证覆盖三种雷达模式超过256个输出、运行期无同步、最终同步和原始字节校验、写入/同步失败、旧periodic行为与配置一致性。另用本次失败会话的真实CDR进行独立存储重放；它不代表重新采集、WASD实车驾驶、完整实时SLAM或几何精度验收。具体执行结果见[本轮记录](../../reports/map_wasd_storage_20260914/README_zh.md)。
