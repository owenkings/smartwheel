# 目录与新增内容规则

项目按功能组织。先阅读根 README 与所属目录 README，再确定文件归属。

| 新增内容 | 放置位置 | 必须同步的内容 |
|---|---|---|
| 正式功能 | `src` 对应功能包 | 功能目录 README、对应测试、接口或操作说明 |
| 用户命令 | `scripts` 的薄入口 | 命令说明、参数与退出码测试；实现放源码包 |
| 配置字段 | `config` 对应配置 | 校验、模板、配置说明和冻结/回放兼容测试 |
| 回归测试 | `tests` 对应功能目录 | 目录说明；小型固定输入放 fixtures |
| 当前用户说明 | `docs/operations` | 根导航或对应功能说明中的链接 |
| 模块设计与接口 | `docs/architecture`、`docs/reference` | 生产者、消费者和兼容边界 |
| 历史过程与验证结果 | 数据根 `dev_archive` | 来源、关联提交、文件清单和实际结论 |

允许新增具有独立职责的目录，不设置含义不明的杂项目录。每个维护目录（包括中间层）必须有 README，写明职责、入口、依赖、新文件位置和对应验证方法。

原始录包、封存快照和厂商原件仅在外层补说明，内部不插文件。自动生成的 build、install、缓存、运行状态，以及本机私有覆盖目录不纳入维护目录 README 覆盖率。

读取目录的程序应明确识别业务文件或使用清单，不能把 README 当作配置、样本或可执行程序。新增文档可能进入软件来源快照，其哈希变化属于软件身份变化，不代表录包、测量值或算法结果变化。

## 开发归档

执行 `python3 scripts/dev_archive sensor_review` 创建独立任务目录。时间采用 UTC，重复名称产生独立后缀，不覆盖既有任务。各分类均有 README；任务的 manifest.json 记录来源及迁移信息。

软件测试入口自动把日志、JUnit 和临时文件归档到新任务的 validation 目录。旧报告保持原件，需要移动时先核验哈希和消费者，再登记旧路径与归档位置。
