# 幅度图辅助双雷达配准

更新：2026-10-08。此功能已接入原有点云选点网页，复用原来的刚体初值算法和 ICP，不另建一套融合程序。

## 1. 与原工具的关系

| 部分 | 原工具 | 本次补充 |
|---|---|---|
| 辨认对应位置 | 在 XYZ 投影点云里选点 | 增加幅度图、前向距离 X 图，像素与原始 XYZ 点编号联动 |
| 求外参初值 | Kabsch/SVD 刚体拟合 | 使用相同求解器和阈值 |
| 精配准 | 多尺度点到面 ICP，含异常点及退化检查 | 使用同一个 ICP；可从选点结果进入 |
| 查看结果 | 两色点云叠加 | 增加明确的前视、顶视、侧视切换，保持米制等比例 |
| 保存 | 保存选点和候选变换 | 继续使用原保存目录和来源哈希，不自动启用候选 |

清晰度主要来自更容易辨认目标的像素图和明确的视图比例。它有助于减少选错点，但不等于测距精度或配准精度已经提高。

## 3. 怎样选点和求变换

1. 先选择“回波幅度”辨认物体；不易分辨时切换“前向距离 X（米）”。幅度是回波强弱，X 是前向坐标，均不是相机照片。
2. 切换“选点”。在左图点一个清楚的物理角点，再在右图点同一个角点，组成一对。也可直接在下方三维点云选点。
3. 用滚轮或 `＋` 放大、拖动平移；“完整图像”恢复。原始像素不插值生成新三维点。
4. 查看鼠标处原始点 ID、行列与 XYZ，核对编号标记在幅度图和三维图中一致。无有效 XYZ 的像素不能组成对应点。
5. 至少三对非共线对应点；建议六至十对，分散于不同位置、高度和深度。不要把两侧不同可见区域的“物体中心”当成同一个物理点。
6. 在步骤 2 先点击“只计算”，查看中文结论、逐点残差及前／顶／侧视叠加；这一步不写入候选文件。需要留存才点击“计算并保存外参初值”。低拟合残差不能证明对应点选择正确。
7. 点击“用此初值继续调整”，无需保存，完整精度矩阵直接传入同页步骤 3。调整后用“只计算 ICP”检查结果；步骤 4 的“保存本次 ICP 结果”保存刚计算的结果，不会再跑一次 ICP。
8. 保存候选后，用未参与求解的特征及其他静态场景检查。不要仅以一张正视图的重合程度判断通过。

末次未保存的浏览、拖动和选点只在页面内；关闭前如需保留，请执行“只导出选点”或“计算并保存外参初值”。退出服务按一次 Ctrl+C；已经确认保存的候选文件会保留。

## 4. 坐标和变换方向

输入已经是每只雷达各自的 FLU 坐标：X 前、Y 左、Z 上，单位米。
幅度图的列为方便乘坐视角观察而逆序显示，但点击位置会反算回原始行列和点编号：

```text
原始点 ID = 原始行 × 宽度 + 原始列
p_left = R_left_right × p_right + t_left_right
```

求出的 `T_left_right` 是完整的右雷达到左雷达变换。左云不动，右云应用它一次；不再额外叠加旧机械间距。SDK 轴方向转换已在驱动中执行，此处不再翻转 XYZ 的 Y 轴。

缩放固定为 1，不允许用镜像或拉伸来制造重合。幅度图保持等像素显示，三维投影保持横纵一米等长；等像素不意味着物体宽高在图上一定等于真实比例。

## 6. 为其他已录的有序点云准备网页输入

输入目录应包含同次双雷达录制的 `capture.json`、`left.npz`、`right.npz`、`left_frames.json`、`right_frames.json`。需要保存 raw XYZ、raw 幅度、逐行布局和帧身份；只有 PLY 或截图无法补回这些信息。

```bash
cd /home/nvidia/wheelchair
OUT="reports/calibration/organized_$(date +%Y%m%d_%H%M%S)"
bash scripts/prepare_lidar_alignment.sh \
  --capture-root reports/lidar_axis_audit_20261006T101151Z/clouds \
  --output "$OUT" --pair-count 3 --max-pair-dt-ms 100

bash scripts/pick_lidar_points.sh \
  --input "$OUT/prepared.json" --scene-index 0 \
  --port 8768 --duration 7200 --no-browser
```

该例复用保留的原始录制，不重新采集。换数据时替换 `--capture-root`。输出必须是新目录，程序不会覆盖旧结果。

| 参数 | 含义 |
|---|---|
| `--capture-root` | 原始有序点云采集目录；支持项目逻辑路径或配置存储内绝对路径 |
| `--output` | 新准备目录；数据仍遵循 U 盘存储策略 |
| `--pair-count` | 从同一次录制中选择的帧对数量，默认 3，范围 1～16 |
| `--left-frame-index` | 指定左侧 raw 数组的零起点帧下标，只准备这一帧和就近右帧 |
| `--max-pair-dt-ms` | 主机到达时间差上限，默认 100 ms；它不代表硬件同步精度 |
| `--scene-index` | 网页打开准备文件中的第几组帧对，从 0 开始 |
| `--duration` | 网页服务最长运行秒数，不是采集时长 |

旧格式 prepared 输入没有幅度数据时，页面会说明原因，原有三维选点仍可用。发现无效身份、单位、布局或哈希时，准备程序拒绝生成输入，并指出问题。

## 7. 只计算、结论与使用范围

| 操作 | 文件行为 | 使用效果 |
|---|---|---|
| 只计算 | 不创建结果文件 | 当前页面显示 SVD 初值、点对残差、中文评估 |
| 计算并保存 | 新建独立候选目录 | 可重新打开作离线初值；不写正式配置 |
| 只计算 ICP | 不创建结果文件 | 当前页面显示精配准、最近邻指标及变化量 |
| 保存本次 ICP 结果 | 新建独立候选目录 | 留存复查；不自动启用 |

人工拟合超出现有 5 cm 最大点对残差门限时显示“当前结果不宜使用”。通过此候选门限仅表示可作离线初值，仍不是正式验收。ICP 的双向重合率及最近邻误差以现有 12 cm 距离门统计，并非独立点对或绝对定位精度；即使重合变好，也需要看变换幅度、退化及未参与计算的物理特征。

工作台默认不载入旧候选；点击“恢复已保存候选”才恢复同一输入、同一场景的历史结果，含义仅为网页展示。实时建图从当前 `hardware_setup` 读外参；离线融合默认从录包配置快照读取，显式 `--hardware-setup` 才覆盖。两者均不扫描这些候选目录。未来明确启用合格相对外参时，车体链为 `T_axle_right = T_axle_left @ T_left_right`。相对配准不能独自确定轮轴参考系。

关闭页面会丢弃未保存计算；先前已存候选不受影响。改动选点或姿态后，页面会区分旧评估与当前输入。不要把“已保存”理解为“已通过”或“已启用”。

## 8. 左右高度和显示比例

默认使用左右共用的显示中心、米制比例和视角，预设、拖动、滚轮联动。每一米在两窗内画成相同长度；“各自适应”可以放大局部，但两窗屏幕大小不再可比。坐标数据和选点 ID 不因显示操作而改变。

两侧仍各自在其原生 FLU 坐标中；共同显示比例不等于外参配准，Z=0 不等于地面。远点、无效回波、遮挡和各侧视野会影响全云范围。检查真实高度应查看同一物理特征在统一参考系内的数值，不能用全云边界或截图像素直接判断。

## 9. 单页工作台与状态传递

当前入口 `/` 与旧 `/alignment` 都提供同一个明亮主题工作台。四步按从上到下排列，导航只滚动定位，不打开新页面。数值矩阵在当前页面内直接传递，不经四舍五入或再次叠加。

- 人工初值未保存也可进入手动调整和 ICP；残差未通过的初值保留醒目结论，只作探索。
- 修改选点使下游结果过期；重新计算并传入后再继续。修改右云姿态会使此前误差指标过期，并禁用保存旧计算。
- 一处计算期间锁定另一处修改，防止延迟响应覆盖新输入。场景 ID 和输入哈希须一致。
- “保存本次 ICP 结果”使用服务器会话内的计算编号，保存相同结果与对应关系，重复同一保存请求返回同一路径。另一次计算会使旧编号失效；服务重启后需重新计算。
- 保存目录、原始点编号、T_left_right 方向、候选门限和正式启用边界保持原有定义。

本次新服务示例：`http://127.0.0.1:8769/`。历史服务器仍可存在，新的代码不会自动重启它们。

## 10. 两种保存操作的区别

| 操作 | 实际保存内容 | 是否运行 ICP |
|---|---|---|
| 保存本次 ICP 结果 | 刚查看的 ICP 变换、匹配点编号与距离、评估指标、计算策略、输入来源及文件哈希 | 不重新计算，保存服务器缓存中的同一次结果 |
| 保存手动调整方案 → 保存当前手动姿态 | 当前手动设置的平移与旋转、当前姿态的几何指标、输入来源及文件哈希；标记为手动未验证候选 | 不运行 ICP 优化，但会评估当前姿态的最近邻几何误差 |

两种操作均在数据盘 `data/calibration/alignment_candidates/<独立版本>/` 新建候选。目录包含 `result.json`、`correspondences.json` 和 `manifest.json`；手动姿态的对应点列表为空，不伪称已完成 ICP 匹配。实际绝对路径以页面保存成功提示为准。

这些是配准结果文件，不是正式配置文件；不会改 `config/hardware_setup.json`，不覆盖原始点云，也不会自动改变实时建图或离线融合的外参。恢复候选只用于网页检查。需要正式使用时另行明确应用。

下拉框改为与工作台一致的浅色菜单，支持鼠标、方向键、Home/End 和输入文字定位；Enter/空格确认，Escape取消，Tab移到下一控件。已选项用勾选标识。菜单禁用状态与原控件同步，不改变点云或算法参数的定义。

## 11. 像素图与三维点云的悬停联动

切换到“选点”，把鼠标停在有效点上，同一侧的像素图与三维点云会用虚线圈预览同一个原始点。先点左侧，再在右侧寻找对应特征时，可直接对照右侧像素图辨认；先从像素图选点，也可对照下方的三维位置。

- 虚线圈表示悬停预览，单击才确认。已选点保留实线圈和编号。
- 图像与点云按同一帧的原始点 ID、行列关联，不通过最近邻猜测。同侧关联不等于左右雷达已自动匹配，左右物理对应仍由用户选择。
- 鼠标移出、拖动视图、缩放、切换模式或计算期间清除悬停预览。无效像素不产生有效选点。
- 像素选择的点若在当前三维视角被遮挡，虚线仅标出其投影并说明遮挡；三维鼠标选点仍只选择可见的实际点。可旋转视角检查。
- 旧数据缺少幅度或逐行布局时保留三维选点，无法凭 XYZ 凭空生成回波幅度图。

## 12. 录制内容与像素图的关系

当前面板“配对录制”调用普通 `mapping_core` 采集链；普通 `mapping_core`、`mapping_cameras`、`all_sensors` 的雷达原始记录均保留 SDK 输出的 XYZ、`intensity`（来自回波幅度）、逐行尺寸和来源信息。像素图由这些数据重新生成，不是另一路摄像头录像；不录摄像头也可使用。

面板从完整录包“准备点云”时，会在所选双帧具备幅度和正确逐行尺寸的情况下，写入 `prepared.json` 的 `organized` 数据供网页使用。实际能否显示以所选场景内容为准；旧 XYZ-only 导入、缺少布局/幅度的来源以及旧版准备文件不保证具有像素图。旧 `tests/calibration/prepare_stability_picker.py` 入口会保留三维点而未导出 `organized`，不要把其页面缺图解释为原始录包一定没有幅度数据。

源端没有返回幅度时，驱动保留 NaN，不补造数值；布局存在也不代表幅度一定有效。此时可在布局与 XYZ 有效的前提下选择“前向距离 X”查看距离像素图。当前网页准备入口每侧支持至多 20,000 个点，若以后提高到更高分辨率，需要扩展该入口，不能把网页拒绝输入误认为录包丢点。
